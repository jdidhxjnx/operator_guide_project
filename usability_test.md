# Протокол испытания документа

**Режим испытания:** Аналитическое испытание по модели интерфейса. 
**Обоснование:** Реальный стенд приложения не предоставлен. Партнер (второй пользователь) отсутствует. Испытание проведено автором после паузы. Поведение приложения не подтверждалось в реальной среде, проверялось только соответствие текста руководства описанию интерфейса из `operator_observations.md`.
**Цель:** Найти пропуски, неоднозначности и опасные советы в `operator_guide.md`.

## Результаты прохода по сценариям

| № | Сценарий | Шаг в руководстве | Ожидание по тексту | Наблюдение (что вызвало вопросы) | Требуемое уточнение (замечание) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | Создание заявки | «Нажмите Отправить. Заявка сохранена.» | После нажатия кнопки оператор должен увидеть номер заявки. | Текст утверждает, что заявка сохранена, но в интерфейсе есть сообщение «Заявка LAB-104 создана» и ссылка «Открыть». Без клика по ссылке проверки нет. | Убрать фразу «заявка сохранена» после клика. Добавить явный шаг: «Нажмите "Открыть", чтобы проверить наличие номера и статуса open». |
| 2 | Прикрепление файлов | «При необходимости исправьте ошибку 4-го файла». | Оператор должен понять, что делать, если файлов больше 3. | В наблюдениях сказано: при 4-м файле появляется сообщение «Можно приложить не более 3 файлов», а введенный текст остается в форме. В руководстве этого не было. | Заменить абстрактное «исправьте» на: «Удалите один файл. Текст в полях Тема и Описание сохранится». |
| 3 | Сетевой тайм-аут | «Если сеть недоступна, повторите отправку». | Оператор не должен создавать дубликаты. | Согласно спецификации, после тайм-аута заявка могла сохраниться. Повторная отправка без проверки списка опасна. | Описать два исхода: 1) заявка нашлась в списке (повтор не нужен); 2) не нашлась (сохранить текст, обратиться в поддержку). Запретить многократные нажатия. |
| 4 | Работа техника | «Нажмите нужную кнопку для завершения». | Техник должен перевести заявку в статус resolved. | Фраза «нужную кнопку» запрещена условиями задания. Также в спецификации сказано, что переход в resolved требует обязательного комментария. | Назвать точную кнопку: «Отметить выполненной». Добавить шаг: «Введите обязательный комментарий о работе. Без комментария завершить нельзя». |
| 5 | Отказ доступа | «Вернитесь назад». | Пользователь должен понять, что доступ ограничен сервером, и не пытаться его обойти. | В наблюдениях есть точный текст: «Нет доступа к этой заявке» и ссылка «К списку». Слова «вернитесь назад» не учат пользователя безопасному поведению. | Указать точный текст экрана. Добавить предупреждение: «Не пытайтесь обойти ограничение (например, изменить ссылку)». |

## Общий вывод по испытанию
В ходе аналитического прохода выявлено 5 существенных недочетов:
1. Ложное подтверждение сохранения по клику.
2. Отсутствие явного указания на сохранение текста при ошибке вложений.
3. Опасный совет при сетевом тайм-ауте.
4. Использование запрещенных абстрактных фраз («нужная кнопка»).
5. Отсутствие предупреждения о серверной проверке прав доступа.

Все замечания переданы в `change_log.md` и исправлены в итоговой редакции `operator_guide.md`. Повторная проверка исправленных мест подтвердила, что шаги стали однозначными и содержат наблюдаемые признаки.

*Примечание:* В таблице указаны изначальные формулировки из раннего черновика руководства. Итоговая версия `operator_guide.md` уже содержит исправленные варианты.
